### v1.21.1 键鼠陪伴边界

- macOS 只需要授予「输入监控」。设置页给出系统请求、打开设置与「重新检测」；只有实际收到一次输入、且「本次确认」增加后，macOS 上才显示为已生效。
- `修复输入监控授权` 只会在用户确认后执行一次 `tccutil reset ListenEvent`，用于从 1.21.0 的 ad-hoc 签名迁移；正常启动不会清空授权。
- 桌面版默认开启，显式关闭过的用户保持关闭。关闭后不再读取全局输入；网页版只在小屋窗口内响应键鼠。
- 持久化文件只保存按本地日期汇总的键盘 / 点击次数、累计数、活跃天数与连续天数，不保存逐次事件时间线；历史最多保留 400 天。
- 今日计数、连续天数与最近 7 天会进入奶糖面板、专注统计、小屋日记和来信；来信只引用聚合值。
- 当前结果来自 Node 测试、隔离浏览器、固定事件流与一台 macOS 真机；不能证明每台 Mac / Windows 的权限弹窗或输入法组合都已通过。

歌单读取、搜索和匹配只提供元数据或播放入口，不提供播放授权。实际播放取决于平台账号、版权、会员与地区；上游接口变化也可能影响可用性。QQ / 网易云模块基于 Simple Music，不宣称官方合作授权。

HTTP 模板的智能唱片机请求使用 `response_format: {"type":"json_object"}`、`temperature: 0.35` 和 1200 token 上限，并在本地严格解析；部分兼容端点拒绝该参数时，传输层会去掉它重试一次。桌面 Codex 模板使用同一份提示词运行 `codex exec`，只取 `--output-last-message` 的最终回答，reasoning、工具事件和临时会话不进入小屋。为了保留用户自己的 Codex 登录与服务商配置，命令会加载用户配置，但用 `notify=[]`、`mcp_servers={}`、`plugins={}` 关闭通知钩子、MCP 与插件，并加 `--ignore-rules` 忽略规则文件；最终仍必须通过同一套 JSON 校验，否则使用本机推荐。HTTP 请求只发送本次计划、约束、输出 schema 与唱片架摘要；Codex 请求还会按本机 CLI 的登录与服务配置发送。两者都不发送封面、曲目详情、待办、日记、手记、信件或 API Key。模型给出的平台 id 不进入本地歌单，播放前再按自动匹配查找可播放版本。

## 手记、来信与备份

- 手记和**整组往来信**只能从回收站永久删除，并需要第二次确认。普通移除仍可恢复。
- 永久删除后只保留 `{ id, purgedAt }` 标记，正文、标签、历史和回信正文不再保存；旧窗口、旧草稿和迟到回信不能复活内容。
- 备份格式为 v4：保留删除标记，但不包含已删除正文。没有删除记录的新 profile 仍可导入外部旧备份；外部旧备份不能推断或撤销从未记录过的永久删除。
- 纪念物独立保存，不因清理手记、整组信件或信箱回收站而消失。
- 收藏、笔记、专注记录、待办、随手记、手记与信件保存在本机。备份用于本机迁移和恢复，不是音乐登录会话或云端同步工具。

「可恢复移除」和「永久删除」必须保持不同语义。此后修改删除、备份或回信流程时，应同时验证旧窗口、迟到回信、旧备份和跨 profile 恢复。

- 真实 QQ / 网易云 / Apple Music / Music Assistant 账号、版权与会员路径仍未完成全量验收。

因此，本分支不能宣称「完整原生验收通过」「同路径安装器升级通过」或「已公证发布」。在这些证据取得前，相关功能继续保留明确边界。

## 本地数据与网络

曲库搜索、封面加载与平台音乐访问会连接第三方；本地保存不是所有功能离线。safeStorage 不能安全加密时拒绝持久保存凭据；动态桌面和桌宠只接收清洗后的显示数据。Music Assistant 更换服务器会清除旧凭据，退出登录使进行中的播放请求失效。

本地文件目录边界、封面重定向校验和音频 URL 白名单是已有防护实现，不构成无漏洞保证。凭据、Cookie、个人备份与签名媒体 URL 不应出现在截图、日志或 Issue 中。
