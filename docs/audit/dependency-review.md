# Desktop dependency review

Registry refresh on 2026-10-11 succeeded: root 0 findings; desktop 15 (9 moderate, 6 high). No dependency versions were changed. The bounded reachability analysis below remains historical; this refresh confirms current advisory counts, not a new proof of non-exploitability.

Reviewed 2026-10-09 against the checked-in lockfile and installed dependency source. This is a bounded reachability review of the 15 desktop findings returned by the 2026-10-08 npm audit, not a new clean audit or a penetration test. The attempted registry refresh on 2026-10-09 did not complete because execution approval was cancelled; current registry availability of fixes is therefore unverified.

## Merge assessment

No new merge-blocking vulnerable input path was identified in the reviewed application entry points. The unresolved advisories remain a release caveat requiring explicit risk acceptance, or upstream remediation before a policy requiring zero findings can be satisfied. Passing unit tests does not establish absence of exploitable paths. No dependency downgrade, cross-major override, or suppression was applied.

The 15 findings include parent-package propagation and correspond to five underlying advisory subjects:

- **music-metadata 7.14.0 / file-type 16.5.4**, nested under NeteaseCloudMusicApi 4.32.0: malformed ASF input can loop. Installed upstream `module/cloud.js` invokes this parser for cloud upload. Current `desktop/music-service.cjs` exposes search, track resolution, account configuration and local playback; it does not pass an arbitrary upstream method or cloud-upload payload. Local file indexing uses the separate top-level music-metadata 11.15.0 via `desktop/local-music.cjs`, not the vulnerable nested parser. Any future cloud-upload feature must resolve this first. Advisories: [music-metadata](https://github.com/advisories/GHSA-v6c2-xwv6-8xf7), [file-type](https://github.com/advisories/GHSA-5v7r-6r5c-r473).
- **basic-ftp 5.3.1**, through get-uri / pac-proxy-agent: a malicious FTP directory listing can consume excessive CPU. Upstream `util/request.js` creates PacProxyAgent only when `options.proxy` is supplied. Current Netease wrappers in `desktop/vendor/simple-music/server/lib/netease-client.ts` construct fixed argument objects without a proxy option; the desktop service does not expose proxy configuration or a generic upstream-call endpoint. Do not add PAC/FTP support without a compatible patched dependency chain. [Advisory](https://github.com/advisories/GHSA-c475-qrg2-pj4r).
- **node-forge 1.4.0**: malformed RSA PKCS#1 v1.5 signatures can be incorrectly accepted. Installed upstream `util/crypto.js` uses public-key parsing and encryption, not signature verification; no forge verification call was found in upstream module/util/plugin sources. This does not certify every path in the shipped dependency. [Advisory](https://github.com/advisories/GHSA-86w9-cpqp-85rv).
- **sprintf-js 1.1.3**, through roarr / global-agent / Electron download and packaging tools: attacker-controlled precision in a format string can cause denial of service. These packages are marked development-only in `desktop/package-lock.json`. Reviewed global-agent log call sites use constant message strings with network values in structured context, rather than as format strings. Packaging/install infrastructure remains in scope for the advisory, even though it is not an application renderer dependency. [Advisory](https://github.com/advisories/GHSA-hp3w-g68c-fv3c).

## Remediation decision

The previous registry check returned no patched node-forge or sprintf-js release and no newer Netease release. The suggested force fix downgraded Netease to 3.47.5 and electron-builder to 26.5.0; this is not an acceptable automatic remediation. Patched basic-ftp 6.2.2 is outside get-uri's declared 5.x range, while the nested music-metadata fix crosses multiple majors. Neither override was imposed without compatibility validation.

Before distributing desktop binaries, rerun both root and desktop audits, inspect newly available compatible patches, and record whether residual risk is accepted. Reassess immediately if cloud upload, custom proxies, signature verification, or remotely controlled build logging is introduced. Root transitive patches already landed for nanoid, PostCSS and source-map-js; the last successful root audit reported zero findings, which should also be refreshed before release.
