# Focus, modes and recovery pass · 2026-10-13

Baseline: merged PR37, `b650916a279690a809a4a1a51a5162852c751af7`.
All browser cases use fresh profiles, synthetic local data, blocked external
requests and muted Chromium. Fullscreen shell events are explicitly mocked.

## Reproduced before fixes

- A failed focus-storage write cleared the new-task input. The task panel did not explain persistence failure.
- Focus backup replacement reported completion without a focus-specific warning after a failed write, and replaced the working copy anyway.
- Reset immediately after a phase deadline could discard the earned session and reward before the interval settled it.
- A collection503 kept the central shelf in “正在整理唱片…” indefinitely.
- Immersive mode → Show tools restored the titlebar but left the focus button at its hidden-titlebar position; the window maximize control intercepted clicks.
- Album-wall Escape closed both its overlay and the underlying focus dock. This was reproduced separately after avoiding the blocked-focus-button path.

## Changes

- Explicit task/settings/import changes are transactional. Failed task add/rename keeps its editable input; backup restore preserves the prior working copy and reports the failed section.
- Notes and timer transitions retain an explicitly unsaved working copy. A failed timer write settles once in memory, without duplicate phase events. Retry saves the current snapshot without restarting the timer.
- Another window's storage event does not silently replace an unsaved note draft; the UI shows a conflict warning.
- Save failures are visible throughout the focus dock and desktop focus/todo widgets. Notes retain their copy-before-loss warning.
- Reset settles an expired round once, then still returns to idle.
- Album-wall Escape is consumed before background shortcuts and ignores held-key repeats.
- Immersive focus positioning follows whether the titlebar/tools are actually shown.
- Loading, failure and retry are separate collection states. Retry is visibly busy/disabled; failed refresh preserves already-loaded items; failed initial loading does not start empty-collection onboarding.

## Regression matrix

`npm run test:focus-ui` covers:

1. Task quota error, retained draft, retry, completion and reload
2. Multiline/CJK/emoji/plain-HTML note draft under quota error and recovery
3. Unsaved note preservation when another window updates storage
4. Timer completion under quota error, repeated wake events and save recovery
5. Timer pause → reload → resume without losing remaining work
6. Transactional focus backup failure and a visible partial-import warning
7. Deadline-boundary Reset with one session/reward and idle final state
8. Long sleep finishing one phase only
9. Immersive Show tools leaves the focus entry clickable
10. Album wall closes before lower layers; held Escape does not cascade
11. Twenty fullscreen/immersion cycles retaining timer and notes; typing shortcuts stay text
12. Collection error → disabled busy retry → successful collection

Each important state is captured at1440×900 and960×600. The suite is wired into
CI with evidence artifacts. Added pure-model tests cover sleep, paused reload,
long-break cadence, skipped rewards and midnight statistics.

The first after-run passed eight of nine cases; the remaining test used the
fullscreen-only accessible name for the normal-mode immersion button. That
selector was corrected to the actual control name before expanded runs. This
is a test correction, not a claimed application fix.

## Boundaries

Real OS fullscreen/Spaces, native taskbar/tray behavior, permissions, updater
installation and account playback are not established by these renderer tests.
No real user records were imported, cleared or modified; no release was made.
